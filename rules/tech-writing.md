# Technical writing — ASD-STE100

All deliverable technical prose (docs, READMEs, procedures, user guides, error messages, release notes, code-adjacent prose) follows **ASD-STE100 Simplified Technical English**. This applies to deliverable/artifact text, not to conversational chat replies or code identifiers.

- **Instructions:** imperative ("Remove the bolt."), one instruction per sentence, maximum 20 words per sentence.
- **Descriptions:** maximum 25 words per sentence; one topic per paragraph, maximum 6 sentences per paragraph.
- **Voice and tense:** active voice only; present tense unless past/future is necessary.
- **Verbs:** no gerunds or complex verb clusters; use simple approved forms ("do", "make sure", "remove", "install"). No "-ing" verb forms except in approved technical names.
- **Vocabulary:** one approved word per meaning, used consistently — never vary synonyms (pick "start", not sometimes "begin"/"initiate"). Substitutions: "make sure" not "ensure"/"verify"; "use" not "utilize"; "start" not "commence"; "if" not "in the event of"; "before" not "prior to".
- **Articles:** always write the articles ("the", "a") — never drop them telegraphically.
- **Nouns:** maximum 3 nouns in a cluster; break longer noun strings apart with prepositions.
- **Warnings/cautions:** put a warning or caution before the instruction it applies to, as a separate, clearly marked sentence.

Technical names and technical verbs specific to the project (API names, commands, domain terms) are allowed as-is, per STE's technical-name rules.
